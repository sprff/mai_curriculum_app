# Расписание университета — frontend

В проекте находятся страницы авторизации, студента, преподавателя и кабинет администратора. Все файлы лежат в одной папке `frontend`, поэтому при добавлении в командный репозиторий ничего дополнительно переносить не нужно.

## Как открыть

Откройте `index.html` в браузере или запустите папку через Live Server в VS Code. Для проверки страниц используйте тестовые аккаунты:

| Роль | Логин | Пароль |
| --- | --- | --- |
| Администратор | `admin` | `admin123` |
| Преподаватель | `teacher` | `teacher123` |
| Студент | `student` | `student123` |

Авторизация демонстрационная — пока что она не проверяет пользователей в настоящей БД.

## Файлы

| Файл | Для чего |
| --- | --- |
| `index.html`, `script.js` | Форма авторизации и переключение по ролям |
| `student.html` | Просмотр расписания группы |
| `teacher-schedule.html` | Просмотр расписания преподавателя |
| `teacher-availability.html` | Выбор доступных и предпочтительных слотов |
| `pages.js` | Демонстрационная логика недель и отметок доступности |
| `admin.html` | Панель администратора и четыре реализованных раздела |
| `admin.js` | Поиск, фильтры, сортировка, открытие и сохранение форм |
| `styles.css` | Общие стили всех страниц |
| `admin.css` | Стили только кабинета администратора |

## Что можно проверить в кабинете администратора

1. Панель управления — карточки с количеством групп, преподавателей, аудиторий, дисциплин и занятий
2. Пользователи — поиск по ФИО, логину или email, фильтрация по роли, создание и редактирование
3. Аудитории — поиск по номеру, сортировка, создание и редактирование
4. Дисциплины — поиск по названию или коду, создание и редактирование
5. Учебные группы — поиск, создание и редактирование

Формы проверяют обязательные поля, дублирующиеся логины, названия и номера, а также корректность числа студентов и вместимости. Добавленные данные остаются в `localStorage` браузера после перезагрузки страницы. Чтобы снова увидеть исходные демонстрационные записи, можно очистить данные сайта в настройках браузера (ключ `mai-curriculum-admin-demo-v1`).

**Всё это демонстрационная работа интерфейса, а не подключение к реальной БД.** Демо-пароли из формы создания пользователей никуда не отправляются и не сохраняются. Новый пользователь пока не сможет войти с созданным логином. Кнопка «Выйти» возвращает на вход без серверного завершения сессии. Настоящие права доступа нужно обеспечить через backend.

Разделы «Преподаватели», «Занятия», «Импорт из CSV», «Генерация» и «Версии расписания» присутствуют в меню, но пока открываются с пустой рабочей областью: их подробные макеты не входили в эту задачу. Пример опубликованной версии, последней генерации и уведомления на панели — демонстрационный контент.

## Что предстоит согласовать с backend

Сейчас в схеме БД `classrooms` отсутствует поле `active`, в `subjects` отсутствует внутренний `code`, в `groups` отсутствует отдельная `students` и `lessons` в качестве счётчиков. Поэтому эти поля на интерфейсе пока демонстрационные. При интеграции нужно выбрать способ хранения активности аудитории, внутреннего кода дисциплины и расчёта численности группы / числа занятий. Отдельно нужно согласовать реальные API и форматы ответа для CRUD-операций.

## Как загрузить в командный репозиторий

Скопируйте содержимое папки `frontend` в уже существующую папку `frontend` вашего репозитория, сохранив имена файлов. После проверки сделайте commit в своей ветке и откройте Pull Request. Убедитесь, что не перезаписали изменения других разработчиков, которые появились в той же папке позже.
