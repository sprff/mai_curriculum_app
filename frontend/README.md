## Что реализовано

- экран входа по макету
- поля логина и пароля
- отправка формы по кнопке и клавише Enter
- проверка пустых полей
- состояние ошибки при неверном логине или пароле
- отдельное состояние для отключенной учетной записи
- заготовка запроса `POST /api/auth/login`
- переход в разные разделы в зависимости от роли
- адаптация под узкие экраны
- локальный демонстрационный режим, чтобы страницу можно было проверить без backend

## Как открыть

Самый простой вариант — дважды открыть `index.html`

Можно также запустить локальный сервер из папки проекта

```bash
python -m http.server 8000
```

После этого открыть в браузере `http://localhost:8000`

## Тестовые данные для демо режима

| Роль | Логин | Пароль |
|---|---|---|
| Администратор | `admin` | `admin123` |
| Преподаватель | `teacher` | `teacher123` |
| Студент | `student` | `student123` |
| Отключенная учетная запись | `blocked` | `blocked123` |

Любая другая пара логина и пароля показывает ошибку из макета

## Как подключить настоящий backend

В `script.js` нужно поменять

```js
const DEMO_MODE = true
```

на

```js
const DEMO_MODE = false
```

Сейчас фронтенд ожидает такой запрос

```http
POST /api/auth/login
Content-Type: application/json
```

```json
{
  "login": "user_login",
  "password": "user_password"
}
```

Успешный ответ должен содержать роль

```json
{
  "role": "admin"
}
```

Поддерживаются роли `admin`, `administrator`, `teacher`, `lecturer`, `student`

Ожидаемые коды ошибок

- `401` — неверный логин или пароль
- `403` — учетная запись отключена

Адрес API хранится в константе `LOGIN_API_URL`, поэтому его можно быстро заменить после согласования backend

## Файлы

- `index.html` — структура страницы
- `styles.css` — внешний вид и адаптивность
- `script.js` — проверка формы, запрос авторизации, ошибки и переход по ролям
