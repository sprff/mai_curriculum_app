# core

Генерация недельного расписания. С БД не работает: бэк присылает снимок данных, core возвращает пары.

## Запуск

```bash
pip install -e ".[dev]"
uvicorn src.main:app --port 8000
pytest
```

```bash
docker build -t core .
docker run -p 8000:8000 -e CORE_TIME_LIMIT_S=120 core
```

`CORE_TIME_LIMIT_S` задаёт лимит времени на одну генерацию, по умолчанию 120 с. Задачи хранятся в памяти процесса, поэтому сервис запускается в одном экземпляре с одним воркером.

## API

`POST /jobs` ставит генерацию в очередь и сразу отвечает `202 {"id": "..."}`. Если данные противоречивы, отвечает `422` со списком проблем.

```json
{
  "classrooms":       [{"id_number": 1501, "capacity": 30}],
  "subjects":         [{"id": 1, "weekly_number_of_lessons": 3}],
  "groups":           [{"id": 1, "size": 25}],
  "teacher_subjects": [{"teacher_id": 1, "subject_id": 1}],
  "group_subjects":   [{"group_id": 1, "subject_id": 1}]
}
```

`GET /jobs/{id}` отдаёт статус: `queued`, `running`, `done` или `failed`. В `done` есть расписание, в `failed` есть текст ошибки.

```json
{
  "id": "...",
  "status": "done",
  "error": null,
  "lessons": [
    {"day": 0, "lesson_number": 2, "group_id": 1, "subject_id": 1, "teacher_id": 1, "classroom_id": 1501}
  ]
}
```

`day`: 0 это понедельник, 5 это суббота. `lesson_number` от 1 до 7.

## Ограничения

- У группы, препода и аудитории не больше одной пары в слоте.
- Аудитория вмещает группу.
- Препод может вести дисциплину, и у группы по дисциплине препод один на всю неделю.
- Одна дисциплина у группы не чаще раза в день.

Мягкие критерии: окна у групп и преподов, первые и поздние пары, больше 4 пар в день, равномерность по неделе.
